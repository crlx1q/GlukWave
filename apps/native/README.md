# GlukWave: Windows, Android и исходники iOS

Настоящий клиент общего GlukWave API на Flutter. Кремовый фон, Manrope с Nunito для казахских символов, терракотовые акценты, обложки и логотип взяты из пользовательского HTML-макета. На компьютере — боковая навигация, на телефоне — три нижние вкладки: Главная, Поиск, Медиатека. Компактный плеер расположен над ними и безопасным нижним отступом. Медиатека нового пользователя пустая: импорт и загрузка создают реальные записи на сервере.

## Как пользоваться

Войди по почте, Google или QR. Настройки площадок обслуживает владелец GlukWave; приложение не просит у слушателя API-ключи. Добавляй реальные аудиофайлы или ссылки через «Источники», ищи музыку на вкладке «Поиск», собирай медиатеку и отмечай любимое обычным заполненным сердцем. Новая библиотека остаётся пустой, пока пользователь не добавит музыку.

Основной язык — English. В «Оформлении» до входа и после него доступны English, Русский, Қазақша, Українська, Deutsch и Español, а также автоматический выбор. Автоматический режим использует регион, определённый сервисом, и язык устройства; при отсутствии подходящего языка используется English. Ручной выбор имеет приоритет над поздним ответом определения региона. Все шесть полных словарей находятся внутри приложения и не требуют загрузки переводов. У гостя выбор сохраняется на устройстве; после входа он хранится в отдельной области аккаунта, работает офлайн и синхронизируется с другими устройствами через обычные настройки. Выход возвращает гостевой выбор. Названия треков, исполнители, личные тексты, плейлисты и сообщения пользователей остаются такими, какими их добавили.

На телефоне меню в верхней панели открывает комнаты, Lo-Fi, источники, скачивания и настройки. Профиль открывается нажатием на аватар. Мини-плеер содержит обложку, название, паузу и сердце; горизонтальный жест по обложке/названию переключает только существующую очередь с ограничением её концов. Движение вверх разворачивает плеер вслед за пальцем и увеличивает реальную обложку до сцены полного экрана. Движение вниз по ручке или обложке сворачивает его. Отмена касания отменяет действие. Кнопки, ползунки и прокрутка текста/очереди управляются отдельно; жесты мышью не переключают треки.

Полный плеер занимает окно целиком, в том числе при открытии трека и комментариев из меню записи. Просмотр внешнего источника сохраняет его официальную кнопку воспроизведения и не добавляет его в нативную аудиоочередь. На компьютере обложка и текст имеют отдельные области прокрутки; на телефоне вкладки показывают трек, текст, очередь и обсуждение. Закрытие кнопкой, Back или Esc оставляет текущий нативный звук работающим. Позиция и длительность показываются как `m:ss`, а с часа — `h:mm:ss`; личный LRC сохраняет стандартные полные минуты и доли секунды.

В настройках девять разделов: аккаунт, оформление, плеер/текст, скачивания, подключения, уведомления, устройства, клавиши, о приложении. На компьютере разделы расположены сбоку, на телефоне — в компактной прокручиваемой полосе. Работают редактирование профиля, полные отдельные палитры светлой, тёмной и AMOLED тем, режим/тип обложки, лимит и очистка автокеша, реальные подключения и управление устройствами. Недоступные внешние возможности честно отключены. Горячие клавиши можно выключить для этого устройства: Пробел, Ctrl+стрелки, Ctrl+F; при вводе текста они не управляют музыкой.

Плейсхолдеры появляются только во время настоящих запросов библиотеки, поиска, текста/комментариев и загрузки обложки. При уменьшении движения они статичны. Пустой результат показывается после завершения запроса, ошибки обложки заменяются аккуратным знаком источника; изображения не блокируют основные кнопки. Для крупных известных HTTPS-обложек SoundCloud приложение запрашивает версию 500×500 и возвращается к исходной при ошибке. Сами метаданные трека, маленькие обложки и пользовательские изображения не изменяются.

## Локальный запуск

Нужны Flutter 3.35.4 / Dart 3.9.2 или совместимая версия и запущенный Node-сервер из корня проекта. Команды выполнять в `apps/native`.

```powershell
flutter pub get
flutter run -d windows --dart-define=GLUKWAVE_SERVER=http://127.0.0.1:4000
```

Текущая Windows Release-сборка 1.0.0+3 подключается к `https://wave.gluk.tech`. Установка — `outputs/GlukWave-Setup.exe`; два независимых флажка управляют ярлыком на рабочем столе и автозапуском в трее. ZIP остаётся дополнительным portable-пакетом. Проверка физических кликов по трею и вывода звука остаётся открытой. Для длинного пути проекта используйте из корня `scripts/build-windows.ps1`, который собирает независимую короткую копию с отдельным кешем. Сборка через временный junction больше не применяется.

Для Android-эмулятора адрес компьютера — `10.0.2.2`. Для физического телефона укажи IP компьютера в той же сети; сервер должен слушать доступный сетевой интерфейс.

```powershell
flutter devices
flutter run -d <ANDROID_DEVICE_ID> --dart-define=GLUKWAVE_SERVER=http://10.0.2.2:4000
flutter run -d <ANDROID_DEVICE_ID> --dart-define=GLUKWAVE_SERVER=http://192.168.1.10:4000
```

`GLUKWAVE_SERVER` — origin API без пути, например `https://wave.gluk.tech`. Обычный вход уже использует адрес, заданный сервисом при сборке. Изменение адреса доступно администратору в разделе «О приложении» и через долгое нажатие на версию в debug-сборке; поля настройки API в обычном входе нет. Debug по умолчанию использует `127.0.0.1:4000` на Windows/iOS и `10.0.2.2:4000` на Android; release — `https://wave.gluk.tech`. На Android HTTP разрешён только debug-манифестом. Для release и iOS используй действующий HTTPS. Наличие домена в конфигурации само по себе не разворачивает сервер.

## Сборка

```powershell
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --debug --no-pub --dart-define=GLUKWAVE_SERVER=http://10.0.2.2:4000
flutter build windows --release --dart-define=GLUKWAVE_SERVER=https://wave.gluk.tech
```

APK появляется в `build/app/outputs/flutter-apk/app-debug.apk`. Для телефона адрес компьютера передаётся при сборке, например `--dart-define=GLUKWAVE_SERVER=http://192.168.3.7:4000`. Компьютер и телефон должны видеть этот сервер в общей сети. Это тестовая сборка с debug-подписью.

Windows требует Visual Studio с Desktop development with C++, Windows SDK и CMake; они установлены. В глубокой папке MSVC не открывает заголовки длиной 263 символа. Из корня запускайте `scripts/build-windows.ps1`: он копирует исходники в отдельную короткую рабочую папку, устанавливает зависимости в отдельный кеш и упаковывает результат. Исходный проект не связывается с временным каталогом и не очищается.

Android release требует собственный keystore и `android/key.properties`, исключённый из Git:

```properties
storeFile=C:/private/glukwave-upload.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=glukwave
keyPassword=YOUR_KEY_PASSWORD
```

```powershell
flutter build appbundle --release --dart-define=GLUKWAVE_SERVER=https://wave.gluk.tech
```

Release не подменяет собственную подпись debug-ключом. Пароли и keystore хранить вне проекта.

Исходники iOS находятся в `ios`. Сборка возможна на macOS с Xcode, CocoaPods и подходящей командой разработчика:

```sh
flutter pub get
flutter run -d <IOS_DEVICE_ID> --dart-define=GLUKWAVE_SERVER=https://wave.gluk.tech
flutter build ios --release --dart-define=GLUKWAVE_SERVER=https://wave.gluk.tech
```

Открой `ios/Runner.xcworkspace` для подписи, provisioning и проверки на устройстве. iOS здесь не собран. Для Firebase нужны также Push Notifications capability, APNs ключ в Firebase и provisioning с push-entitlement; один Dart-define их не создаёт.

## Воспроизведение и синхронизация

Собственные загруженные аудиофайлы воспроизводятся через `just_audio`; Windows использует движок `just_audio_media_kit`, Android/iOS — нативный аудиодвижок. `audio_service` предоставляет Android foreground service, системную медиакарточку, блокировку экрана и команды гарнитуры; `audio_service_win` подключает системные медиакоманды Windows. Настроены audio focus, пауза при отключении наушников, очередь, seek, громкость, shuffle и repeat.

Прямое воспроизведение, фоновая работа и offline доступны только для источника, которому сервер реально предоставляет аудиофайл. SoundCloud и YouTube воспроизводятся в постоянном встроенном официальном плеере, который расположен над навигацией Flutter и остаётся в приложении при переходе между страницами. Очередь и команды получают фактическое время, ready/playing и завершение от официального плеера. YouTube на Android ставится на паузу при переходе приложения в фон; фоновые возможности встроенного SoundCloud ещё требуют проверки на физическом устройстве. Spotify и Яндекс Музыка без доступного аудиофайла открываются только по явному действию «Открыть источник». Автоматического перенаправления при выборе трека нет. Windows для встроенных плееров требует установленный Microsoft Edge WebView2 Runtime; отсутствие среды отображается понятным сообщением. Реальная проверка звука, WebView2 и встроенных плееров на Windows/Android остаётся открытой. Подключение аккаунта импортирует доступные метаданные и плейлисты через настроенный серверный интегратор.

Сессия сохраняется в `flutter_secure_storage`; API и Socket.IO используют непрозрачный Bearer, отдельно от URL. При включённой CAPTCHA почта и Google входят через браузерный мост: браузер показывает CAPTCHA/OAuth, пользователь подтверждает вход, приложение получает однократную сессию. QR отображается на компьютере и сканируется мобильным клиентом с явным подтверждением устройства. Ключи площадок, Google и Turnstile задаются на сервере.

Комнаты используют серверную временную шкалу, поправку часов, коррекцию рассинхронизации и права участников. Сообщения и команды отправляются через Socket.IO. Управление своими устройствами включает play/pause, следующий/предыдущий трек, seek, громкость и перенос текущего трека. Ответ на удалённый запуск отправляется после готовности и фактического состояния `playing` движка; ошибки передаются инициатору.

В одной локальной сети можно выбрать сервер вручную или найти его через UDP-порт 4001, если на сервере `LAN_DISCOVERY=true`. Перед подключением пользователь выбирает найденный адрес. Интернет для локального сервера с локальными файлами не требуется; сервер всё равно должен работать и быть доступен обоим устройствам.

## Файлы и настройки

Автокеш включён по умолчанию; лимит — 1 ГБ, настраивается. Реальные файлы и JSON-манифест находятся в каталоге поддержки приложения, раздельно для пользователя и адреса сервера. Запись манифеста, изменения размера и удаление выполняются последовательно. Автокеш вытесняет старые файлы; ручные загрузки сохраняются до удаления пользователем. Активный файл не удаляется во время воспроизведения. Выход останавливает плеер, отменяет загрузки, удаляет приватный кеш и сохранённую медиатеку текущей сессии.

Экран загрузок показывает фактический статус файлов, размер и процесс загрузки. Есть плейлисты, избранное, история, импорт CSV/JSON, корректировка раскладки поиска, комментарии с временем, LRC/обычные тексты и строка текста под обложкой. Профиль поддерживает реальные загрузки изображений/GIF, баннер, теги и бейдж тарифа. Тарифы изменяет сервер; Checkout/Portal открываются только при настроенном Stripe, premium подтверждает серверный webhook.

Логотип анимируется только в интерфейсе, есть режим уменьшения движения. Windows закрытие окна сворачивает приложение в трей. Один клик по трею показывает быстрый плеер, два клика открывают или скрывают главное окно. Мини-плеер — отдельный режим этого же окна 410×116 поверх остальных окон; для официального источника высота увеличивается, чтобы его элементы управления оставались видимыми. При выходе из режима восстанавливаются размеры и максимизация. Название окна меняется на трек только при воспроизведении.

Оформление доступно до входа и в настройках: светлая, тёмная или системная тема, отдельные палитры фона/поверхностей/текста/акцента, HEX и готовые акценты. Скругление 8–38 px, скорость движения 0,3–2×, уменьшение движения, компактная плотность, свечение вокруг обложки и три рисуемые волны (Silk, частицы, Bloom) меняют реальные компоненты. Обложку в плеере можно наклонять мышью или долгим касанием с движением пальца, переключать винил/CD или плоский вид. Вращение диска прекращается при паузе и уменьшении движения. Сброс восстанавливает выбранную палитру и исходные эффекты, сохраняя палитру второй темы.

Гостевые изменения сохраняются только на устройстве. Для аккаунта локальные изменения применяются сразу и сохраняются даже без сети; отправка через `PATCH /api/settings` повторяется при доступности сервера. Отправляются только изменённые поля, чтобы другая палитра не затиралась при настройке с другого устройства. При выходе восстанавливается гостевое оформление, запоздавший ответ старой сессии игнорируется. Режим системной темы следует яркости ОС. Экран лицензий содержит Nunito OFL; текст лицензии включён в приложение. Lo-Fi доступен и в нативном клиенте до входа или из меню «Твой мир»: оригинальные рисованные сцены, местные часы, zen-режим и отдельная настоящая атмосфера. Выбор сцены и настройки сохраняются на устройстве. Он не требует загруженного музыкального каталога.

## Discord и push

Windows Rich Presence использует официальный Discord IPC локального запущенного Discord. Сервер должен возвращать действующий `config.discord.clientId` для приложения Discord с нужными art-assets. Привязка Discord-аккаунта через OAuth и Rich Presence — разные операции. При недоступном IPC или Client ID приложение показывает причину, статус не подделывается. Кнопки ведут на трек и приглашение в активную комнату.

Для Rich Presence веб-плеера включи локальный мост в Windows-настройках, скопируй код сопряжения и введи его в веб-клиенте. Мост слушает только `127.0.0.1:4002`, проверяет Origin и `X-GlukWave-Pair`. Он работает только при запущенном приложении; сетевой доступ ко всем интерфейсам не включается.

Мобильные push включаются по желанию пользователя и только при настроенном FCM на сервере. Firebase Options передаются при сборке:

```powershell
flutter build apk --debug --dart-define=GLUKWAVE_SERVER=http://10.0.2.2:4000 --dart-define=FIREBASE_API_KEY=YOUR_API_KEY --dart-define=FIREBASE_APP_ID=YOUR_ANDROID_APP_ID --dart-define=FIREBASE_PROJECT_ID=YOUR_PROJECT_ID --dart-define=FIREBASE_SENDER_ID=YOUR_SENDER_ID
```

Используй отдельный `FIREBASE_APP_ID` соответствующей платформы и зарегистрированный package/bundle `tech.gluk.glukwave`. На сервере нужны `FCM_PROJECT_ID`, `FCM_CLIENT_EMAIL`, `FCM_PRIVATE_KEY`. Без них UI честно сообщает, что push не настроен. Android разрешение уведомлений и камера для QR запрашиваются системными библиотеками при использовании соответствующей функции.

## Проверка и границы

Тесты проверяют права комнаты, проекцию позиции, текст, offline-флаги, API-заголовки и ошибки на реальном loopback HTTP-сервере; конкурентный кеш и отмену записи; адаптацию компонентов с настоящим Nunito на ширинах 320, 390, 768, 1280. Журналы проверки находятся в корневом `work/qa/native-*.log`.

Тесты оформления дополнительно проверяют изменения цветов и компонентов через панель, отдельные палитры и сброс, гостевой перезапуск, offline-правки с повторной синхронизацией и сохранением чужой палитры, защиту при смене аккаунта, системную яркость, скругления и компактную плотность. Тесты языка проверяют одинаковые ключи и параметры шести каталогов, реальные множественные формы, числа и даты, переключение через настоящую панель, заголовки запросов, guest/account offline-сохранение и защиту от запоздавшего определения региона. Снимки входа, главной, настроек и плеера на каждом языке сохраняются в `work/qa/native-language-*.png`; русские названия тестовой музыки при этом намеренно не переводятся.

Nunito подключён шестью настоящими статическими начертаниями 400–900 из `assets/fonts`, каждое с соответствующим весом OS/2 и названием стиля. Они получены из сохранённого исходного `assets/Nunito.ttf` (переменный шрифт с исходным весом 200) инструментом `tool/instantiate_fonts.py` / FontTools 4.66.1. Геометрия каждого веса рассчитана из исходного шрифта, набор символов и авторство Nunito Project Authors сохранены; все файлы остаются под включённой SIL OFL 1.1. Обычной сборке и тестам FontTools не нужен. Widget-снимки загружают те же шесть файлов из реального `FontManifest.json`; тест проверяет метаданные файлов и фактическую разницу растеризации обычного и жирного текста. Метаданные и SHA-256 находятся в `work/qa/native-font-metadata.json`.

На узком телефоне ярлыки избранного/скачиваний расположены друг под другом. Длинные названия вкладок плеера остаются целыми в горизонтально прокручиваемой полосе с кнопками не ниже 48 px; свайп по ней не переключает аудиоочередь. Высота блока волны растёт по содержимому, чтобы перевод и реальные метрики шрифта не обрезали текст.

## Connect и встроенные источники: проверка текущего этапа

Установка сохраняет постоянный deviceId; каждый запуск имеет отдельный surfaceId. При общем воспроизведении на другом устройстве показываются настоящий трек, очередь, время и громкость удалённого выхода, а местный аудиодвижок не запускается. Play/pause/seek/volume и выбор трека направляются активному выходу. «Слушать на этом устройстве» явно переносит звук, переключатель раздельного прослушивания по умолчанию выключен. Выход устройства из аккаунта удаляет его сессии; получение session:revoked возвращает клиент ко входу. Запоздалые GET /connect и меньшие state.revision отбрасываются. Местная сохранённая громкость не заменяется состоянием своего выхода с сервера. Только подтверждённый 404 старого развёртывания отключает Connect и пропускает новый device:claim; сеть и 500 не выдаются за неподдерживаемую возможность.

Комната закрепляется над содержимым с онлайном/переподключением и выходом. Создание отправляет реальную visibility public/private; приватный режим выбран изначально. Каталог общедоступных комнат, друзья и временные джемы требуют следующего этапа интерфейса. Права комнаты продолжают задаваться сервером.

Flutter widget и transport tests проверяют реальную композицию desktop1280/mobile390 в светлой, тёмной и AMOLED темах, нативный вход, колесо громкости, shared/independent Connect, сохранение местной громкости, строгие track/transfer запросы, защиты от старых ответов, callback bridge и очередь без уничтожения при смене страниц. Изолированные фикстуры в тестах не входят в продукт. Снимки: work/qa/native-connect-home-*.png, native-connect-devices-*.png и native-connect-room-create-*.png. Физические клики по трею, реальный WebView2/Android player, звук и поведение источников при сворачивании требуют отдельного прогона на устройствах; успешные widget tests не подтверждают эти пункты.
