## SoundCloud: живой источник

Публичный поиск `Forss` вернул настоящие результаты без ключей приложения. Официальный widget **Flickermood — Forss** действительно играл: SDK сообщил `paused:false`, позиции11,58с и42,14с; пауза GlukWave дала `paused:true` около52,3с. Заголовок страницы сменился с имени трека обратно на GlukWave. Это проверка воспроизведения, а не только изменения иконки.

Серверная форма звука этого трека получена с `wave.sndcdn.com`:1800samples,213,886с, source=`soundcloud-envelope`, available=true. Никакой записанный аудиопоток SoundCloud для этого не скачивался.

**Непрерывность по v6:** живой SDK подтвердил последовательность позиций 29,105 → 38,094 → 50,391 → 70,094 → 146,355 → 160,844 → 184,907 → 193,245 → 199,837 с. Проверены раскрытие, очередь, закрытие клавишей ESC, настройки, смена темы и акцента, главная и медиатека. На каждом шаге `paused:false`, ровно один iframe, тот же DOM frame и контроллер SDK; переходы не породили событий PAUSE/PLAY. Подробное доказательство — `work/qa/web-v6-soundcloud-regression.json`.

Длинные времена проверены на границах 3599/3600/3661/4800/7200 с, а также отрицательных и нечисловых значениях. UI показывает 4800 с как `1:20:00`. Сервер принимает обычный LRC `[80:00.00]` и явный часовой `[1:20:00]` как одну позицию 4800 с; стандартный экспорт LRC сохраняет минуты и дробную часть.

После настоящего seek к концу Flickermood получены три живых SDK FINISH: repeat off остановил текущий трек, repeat one запустил его сначала с тем же iframe, repeat all перешёл к следующему настоящему аудиофайлу из изолированной очереди. Доказательство — `work/qa/web-v6-soundcloud-finish.json`. Эти проверки проводились до языковой миграции; после неё отдельно проверяется сохранение текущего плеера при смене языка.
