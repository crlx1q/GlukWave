# GlukWave

Музыка, библиотека и совместное прослушивание в одном пространстве. Настоящий локальный Node.js сервер, React веб-клиент и общий Flutter клиент для Android/Windows. Дизайн основан на переданном `Gluk-Wave-v2.html`: кремовый фон, Manrope с Nunito для казахских символов, терракотовые акценты и тёмный плавающий плеер. Исходные материалы пользователя не изменены.

## Быстрый старт

Требуется Node.js 24+. В корне проекта:

```powershell
npm install
npm run keys
npm run dev
```

Сайт: <http://127.0.0.1:5173/>. Музыкальное приложение: <http://127.0.0.1:5173/app/>. Сервер: <http://127.0.0.1:4000>. Веб и сервер нужно запускать вместе. Старые музыкальные ссылки вроде `/#home`, QR/OAuth и приглашения сохраняются. Без ключей площадок уже работают публичный поиск SoundCloud и официальный плеер, регистрация, загрузка своих MP3/FLAC/WAV/OGG/M4A, плейлисты и комнаты. Пустая личная библиотека означает отсутствие импортированной музыки; фиктивных песен или пользователей в поставке нет. Пользователь не получает ключи API и не настраивает интеграции сервера: это делает владелец развёртывания один раз.

При стандартной локальной конфигурации SQLite находится в `var/glukwave.sqlite`, загруженные оригиналы — в `var/media`, временные файлы — в `var/tmp`. Настройки владельца могут переключать базу на MongoDB Atlas, а оригиналы — на приватный R2. В текущем рабочем проекте 8 октября настроены и проверены Atlas/R2; приватная конфигурация в архив не включается. Без SMTP письма разработки реально записываются в `var/mailbox`; это не отправка на почту. `.env` и вся `var` исключены из Git. Автокеш и ручные загрузки клиента сохраняются на устройстве; сервер хранит только собственные загруженные оригиналы и метаданные площадок.

В production `npm run build`, затем `npm start`: сервер отдаёт собранный веб-клиент. Установить `APP_URL=https://wave.gluk.tech`, разрешённый origin и реальные Turnstile/SMTP ключи, `REQUIRE_EMAIL_VERIFICATION=true`. Без этих условий production сервер откажется запускаться.

## Настройка

Все параметры в `.env.example`, подробности в [docs/SETUP.md](docs/SETUP.md). `npm run keys` создаёт `.env` и генерирует ключ шифрования OAuth-токенов и Web Push. Имеющиеся ключи сохраняет. Смена ключа шифрования требует повторного подключения площадок, поэтому его нужно сохранить при переходе на MongoDB.

Администратор: добавьте собственную почту в `ADMIN_EMAILS` **до регистрации**, перезапустите сервер и зарегистрируйтесь с ней. В production почта должна быть подтверждена. Не поставляется общий административный пароль. Для существующего аккаунта роль можно выдать из административной консоли другого администратора.

## Клиенты

- `apps/web`: React, TypeScript, Vite, IndexedDB, PWA, Media Session, официальный плеер для внешних источников.
- `apps/native`: Flutter Android/Windows/iOS исходники; audio_service, just_audio, Windows media-kit/SMTC, локальный кеш, трей, мини-плеер и Discord IPC.
- `apps/server`: Express, Socket.IO, SQLite/MongoDB, локальные файлы/R2, OAuth PKCE, сессии, комнаты, библиотека, измеренные формы звука, push и административная консоль.

Оформление включает отдельные палитры светлой, тёмной и AMOLED тем, цвета HEX, скругление, скорость/отключение движения, плотность, свет вокруг обложки и три вида волны. Bloom адаптирован из полученного официальным CLI компонента Originkit; параметры формы совпадают в вебе и Flutter. Волна реагирует на курсор/касание и на измеренные данные аудио, без выдуманного сигнала. Винил/CD, наклон/плоская обложка, Lo-Fi со сценами и отдельным звуком атмосферы продолжают функции исходного макета. Уведомления об авторстве и лицензии — [docs/THIRD-PARTY.md](docs/THIRD-PARTY.md).

## Языки и сайт

Основной язык — английский. Веб, сайт и Flutter содержат локальные переводы на английский, русский, казахский, украинский, немецкий и испанский. В настройках можно выбрать язык или автоматический режим. Ручной выбор сохраняется локально и синхронизируется в аккаунте вместе с оформлением; словари не требуют интернета. Музыка, имена и пользовательские тексты сохраняют исходный язык.

Автоматический режим определяет страну через локальные серверные IPv4/IPv6 диапазоны, затем использует язык браузера/телефона и английский. При тестировании на localhost или в домашней сети страна отсутствует. IP не передаётся стороннему геосервису. Данные и лицензия находятся в `apps/server/data/geoip`; обновление — `npm run geoip:update` и перезапуск сервера. Подробности прокси и хранения — [docs/SETUP.md](docs/SETUP.md).

Сайт-визитка на `/` рассказывает о приложении, открывает `/app/` и показывает реальные доступные сборки. `/api/releases` выдаёт только зарегистрированные файлы с совпадающими размером и SHA-256; недоступные платформы не получают фиктивную кнопку скачивания. После успешной компиляции и проверки APK владелец регистрирует его через `scripts/register-release.mjs`. Текущее состояние сборок и проверок — [outputs/VERIFICATION.md](outputs/VERIFICATION.md).

Серверные интеграционные проверки используют отдельную временную SQLite базу и синтезированное аудио только для проверки декодирования/потока. Проверяются чужие файлы, права комнат, реальное byte-range воспроизведение, повторное использование QR/паролей, команды устройств, отказ autoplay и хранение данных.

## Границы внешних интеграций

Публичные поиск и метаданные SoundCloud читаются сервером без ключей приложения, а треки играют в официальном widget. Для OAuth-импорта своей библиотеки SoundCloud нужны ключи владельца сервера. Поиск и импорт Spotify/YouTube используют API с серверными ключами. OAuth открывает реальный вход площадки. Неподключённые возможности показывают обычное сообщение о недоступности, техническая диагностика остаётся у администратора. YouTube Music не предоставляет отдельный подключённый API: импортируется библиотека доступных YouTube плейлистов/видео. Яндекс Музыка поддерживает импорт экспортированных CSV/JSON со ссылками и официальный iframe; прямого входа и поиска в закрытой библиотеке Яндекса в этой версии нет.

Полный Spotify SDK требует Premium, а YouTube ограничивает загрузки и фоновое воспроизведение. Эти источники не преобразуются в скачиваемые файлы и не обходят подписки. Фоновый нативный плеер и offline работают с загруженными аудиофайлами. Discord OAuth связывает аккаунт; Rich Presence обновляет работающий Windows клиент через локальный IPC. Веб может подключиться к включённому desktop bridge с отдельным кодом сопряжения.

Free/Beta/Unbound имеют серверные ограничения; Beta имеет уровни Unbound и выдаётся администратором. Unbound поддерживает настоящий Stripe Checkout/Customer Portal и подписанный webhook; для запуска оплаты нужны ваш Stripe-аккаунт, ключи, recurring Price и webhook secret. Без ключей оплата отключена. Никаких фиктивных оплат или активаций нет.

Перед публичным запуском нужны реальные аккаунты/ключи сервисов, тест OAuth с вашими аккаунтами, SMTP/Turnstile/FCM, SSL и проверки собранных нативных приложений на реальных устройствах. Эта поставка не объявляется завершённым публичным сервисом.
