# Устройства, сессии и комната — итерация 1.0.0+5

Браузер, Windows и Android теперь показывают реальный выбранный выход аккаунта. Вкладки браузера — отдельные поверхности одного устройства; Windows-программа и браузер на том же компьютере имеют разные подписи. Общий режим включён по умолчанию: остальные клиенты показывают трек/очередь/позицию и управляют выходом, одновременно звук не запускают.

Перенос сначала приостанавливает старый выход и ждёт загрузки/готовности нового. Успех подтверждается адресным клиентом; ошибка возвращает прежний выход. Поздний ответ от отключённой сессии не захватывает воспроизведение. В комнате состояние ведущего и выбранное устройство каждого участника разделены. Громкость собственного аппарата не требует права менять общую очередь; команды общей очереди требуют права комнаты. Выход, удаление комнаты, logout и отзыв сессии очищают закреплённое участие.

В настройках безопасности доступны настоящие входы, текущая сессия, последний контакт и онлайн. `GET /api/account/sessions`, `DELETE /api/account/sessions/:id`, `DELETE /api/account/sessions` завершают выбранный либо остальные входы; публичные идентификаторы не раскрывают токены. Отзыв отключает сокеты и связанные устройства, отменяет ещё не завершённый OAuth. Срок авторизации проверяется повторно при подтверждении переноса.

## Вход в площадки

Callbacks формируются из отдельного OAuth base и точных адресов каждого источника. Сервер не доверяет произвольному Host. Веб OAuth связан с исходной cookie-сессией; native получает свой flow. Состояние, PKCE, срок и одноразовость проверяются; отозванный вход не завершает подключение. Результат веб-входа возвращается только в разрешённый origin.

Spotify требует точного совпадения адреса с кабинетом приложения и HTTPS; разрешённое исключение HTTP — loopback IP. LAN HTTP `192.168…` и `localhost` не подходят. [Правила Spotify](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri).

YouTube search key и Google OAuth client — разные настройки. Реальный вход требует OAuth client, callback и разрешённых scopes. [Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [YouTube OAuth](https://developers.google.com/youtube/v3/guides/auth/server-side-web-apps). Диагностика точных callback и готовности находится только в админке, без секретов. Живые аккаунты владельца не авторизовывались в этой проверке.

## Проверка и границы

50 серверных тестов включают два браузерных окна и телефон, отсутствие дублей устройств, перенос с успехом/ошибкой, комнату без выхода, поздний ACK от истёкшей сессии, права участника, отзыв входов и OAuth cookie/PKCE/replay. Flutter: 132 теста, анализатор без замечаний, 30 свежих тематических композиций устройств/безопасности/комнаты/EQ. Веб проверяется на отдельном локальном сервере с собственным WAV, без аккаунта и воспроизведения владельца.

Это проверка сетевого протокола, контроллеров, браузера и widget-композиций. Физические Windows/Android, аппаратный звук, OAuth владельца и долгие сетевые сбои остаются отдельным этапом. Клиенты собираются с `https://wave.gluk.tech`; новый backend туда пока не публиковался. Все незавершённые направления сохранены в ROADMAP.md.
