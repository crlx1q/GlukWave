# GlukWave — общие функции веба и Flutter, 9 октября 2026

Эта итерация продолжает существующий проект. Реализация клиента не означает проверку физического телефона или публикацию сервера на домене. Фактические сборки и результаты проверки фиксируются в `outputs/VERIFICATION.md`.

## Общие данные

Веб, Windows и Android обращаются к одной серверной модели: музыкальные вкусы, друзья, джемы, публичные плейлисты, приватность и статистика. Контракт находится в `PARITY-CONTRACT.md`.

- Вкусы: настоящий каталог артистов, поиск, выбор/удаление, добровольный трёхэтапный сценарий, сохранение незавершённого выбора и явный пропуск. Угаданные артисты не подмешиваются в продукт. Личные артисты из закрытых загрузок не открываются другим аккаунтам.
- Рекомендации: ранжирование доступных треков по выбранным артистам, фактическим слушаниям, избранному, истории и жанру настроения. Это прозрачное ранжирование существующего каталога; внешняя рекомендательная модель и полный каталог музыкальных площадок не заявляются. Автоматические предпочтения можно выключить и сбросить.
- Друзья: поиск ника/имени, заявки с проверкой получателя, принятие/отказ/удаление, онлайн, текущая доступная музыка и устройство. Почта и пароль не входят в публичный профиль. Приватность активности проверяется сервером.
- Джем: явно созданное скрытое прослушивание для друзей ведущего, максимум пять участников, общая очередь ведущего. Слушатель может поставить на паузу свой выход. Закрытие ведущим удаляет джем и участие; отключение ведущего даёт время на переподключение, затем закрывает джем. Обычные комнаты сохраняют свои права и лимиты.
- Плейлисты: публичность/приватность, поиск опубликованных подборок, отдельная страница, коллаж из 1–4 обложек или своё изображение. Сервер запрещает публикацию закрытого аудио. Заменённые изображения удаляются через общий механизм локального/R2-хранилища с повтором при временном сбое.

## Аккаунт и администрирование

Смена почты проверяет текущий пароль и отправляет одноразовую ссылку на новый адрес. Старый адрес действует до подтверждения. Ссылка привязана к аккаунту и истекает; подтверждение отзывает остальные сессии и прежние Google-привязки. Без настроенной доставки сервер не обещает отправленное письмо. Для Google-аккаунта без пароля сначала предусмотрено восстановление по почте.

Удаление аккаунта блокирует вход, отзывает сессии, закрывает собственные комнаты и удаляет личные данные/медиа/социальные связи. Неудачные операции удаления объекта остаются в очереди очистки. Администратор не может удалить себя через административный маршрут. Бан теперь отзывает сессии окончательно: разбан не оживляет старый токен.

Админка получает контроль регистрации, удаление аккаунта, сводную статистику и загрузку пакетов. Пакеты загружает только администратор из настроенного списка владельцев. Проверяются размер, платформа, формат и SHA-256; отдельное хранилище новых релизов не перезаписывает локальные поставки из `outputs`. Поле типа подписи в манифесте не является проверкой Authenticode или подтверждением допуска в магазин.

Free сохраняет доступность: темы, базовый акцент, размер текста и reduced motion. Новые изменения подробной палитры/геометрии и импорт требуют Beta/Unbound; уже сохранённые настройки не ломаются. Комнаты/устройства и анимационные изображения ограничиваются сервером.

## Статистика и нагрузка

Время считается по принятым событиям настоящего выбранного выхода аккаунта, с ограничением прошедшим временем. Зеркальные вкладки, перемотка и смена устройства не умножают время. Запись накоплений выполняется пакетами; память ограничена. Публичная статистика выключена по умолчанию и включается владельцем профиля.

Локальная проверка одного сокета в комнате с очередью из 100 записей: 24 события за примерно 46 секунд, четыре записи состояния устройств/Connect, ноль повторных рассылок полного аккаунта. Это короткий тест Node-процесса в SQLite, без физического аудио; он не доказывает отсутствие всех утечек или производительность Atlas под большой нагрузкой. Пакетные накопления слушаний учитываются отдельно от числа checkpoint-записей.

## Windows DSP

Прямое аудио Windows использует собственный адаптер существующего pinned mpv. Десять equalizer-фильтров получают planar float через родной фильтр mpv; предусиление меняет software volume, сохраняя пользовательскую громкость и не затрагивая отдельный дождь. Минимальный поставляемый FFmpeg не содержит volume/aresample-фильтров: исходная попытка с ними была отклонена реальным DLL-тестом и заменена рабочей цепью.

Поставляемый DLL проверен на созданном для QA WAV через null-output: декодирование, движение позиции, запуск цепи без ошибок, применение предусиления и отключение фильтра подтверждены. Проверка return code защищает ошибки API; mpv может принять свойство и сообщить позднюю ошибку фильтра, поэтому return code сам по себе не считается полной проверкой обработки. Физический звук и Android audio effects остаются отдельными испытаниями.

## Границы готовности

Новый backend не публиковался на `wave.gluk.tech`. Живые OAuth-сценарии зависят от зарегистрированных callback-адресов и приложений владельца площадок. Прямое аудио GlukWave используется при подтверждённом разрешении источника; техническая доступность потока не подменяет разрешение. Где разрешения нет, официальный плеер не скрывается обманным способом.

Дополнение 10 октября: IPC/локальный мост заменены серверным OAuth headless-адаптером, с тарифными проверками и общей моделью Connect. Протокол, проверки и ограничения описаны в [DISCORD.md](DISCORD.md). Живая публикация пока не подтверждена: ключи Discord-приложения отсутствуют; bare headless HTTP endpoint не имеет стабильного публичного REST-контракта. Старые +6 сборки эту интеграцию не содержат.

Физические проверки Windows ↔ Android, экран блокировки, трей, длительное проигрывание, реальный Discord, живая почта/OAuth, production-подписи и публичное развёртывание отмечаются отдельно. Предыдущие установщики и APK сохраняются.
