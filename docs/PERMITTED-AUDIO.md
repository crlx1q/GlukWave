# Прямое разрешённое аудио GlukWave

Новый слой отделяет поиск и техническую доступность от права воспроизведения/скачивания. Для разрешённого аудио клиенты используют собственный плеер, общую очередь, устройства и локальный кеш; сторонний iframe для такого трека не создаётся. В +10 неподтверждённое разрешение возвращает AUDIO_UNAVAILABLE; внешний descriptor источника остаётся только метаданными каталога, без автоматического виджета. Наличие CDN URL, авторского разрешения на персональное скачивание или совпадения Spotify не лицензирует распространение сервисом.

## Адаптеры

- SoundCloud: yt-dlp получает настоящие метаданные, лицензию, обложку и доступный аудиопоток без платного API. Публичный поиск работает отдельно. MP3 конвертируется только по запросу разрешённой загрузки.
- YouTube/YouTube Music: yt-dlp извлекает доступный поток, ytmusicapi ищет songs, Deno выполняет необходимые JavaScript challenges. Для собственных потоков предпочтителен исходный M4A/MP3; HLS пока не ретранслируется этим endpoint.
- Spotify: отдельная среда spotDL получает метаданные и кандидатов YouTube Music/YouTube/SoundCloud. Исходный MP3 Spotify не извлекается. Сопоставление требует имени автора/названия/версии и известной длительности в пределах max(5 секунд, 3%). Для собственного воспроизведения администратор указывает конкретный разрешённый URL аудио, совпадение повторно проверяется.

У адаптеров отдельные Python environments и зафиксированные версии. Их независимое обновление: `scripts/prepare-extractors.ps1 -Adapter ytdlp`, `-Adapter spotdl`, `-Adapter deno`; сначала обновляются соответствующие requirements/версия runtime, затем проверяются настоящие запросы. Windows setup выполнен локально; Dockerfile содержит Linux environments и Deno, но сборка Docker этой итерации не проверялась.

Источники документации: [yt-dlp](https://github.com/yt-dlp/yt-dlp), [EJS/Deno](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [ytmusicapi search](https://ytmusicapi.readthedocs.io/en/latest/reference/search.html), [spotDL](https://spotdl.readthedocs.io/en/latest/).

## Разрешения и API

Автоматический режим принимает явную лицензию CC0/CC BY/CC BY-SA в метаданных источника, включая стандартную YouTube Creative Commons attribution. Он не принимает NC, ND и all-rights-reserved. Приложение сохраняет автора/название/ссылку источника; лицензии и необходимые атрибуции должны соблюдаться владельцем сервиса.

Администратор может записать реальное разрешение правообладателя либо договор: `PUT /api/admin/tracks/:id/audio-permission` с `stream`, `download`, `convert`, `basis`, HTTPS `evidenceUrl`, необязательным сроком. Для Spotify обязателен точный `audioSourceUrl`. Поле является записью доказательства, а не выдачей прав. GET читает текущую запись; DELETE удаляет её. Всё доступно в карточке админки и журналируется; обычный пользователь ключей или разрешений не настраивает.

`GET /api/catalog/search?q=…&source=youtube|soundcloud|spotify` возвращает `title`, `artist`, `album`, `duration`, `cover`, `source`, `track_id`, `audio_url`. В выдаче `audio_url:null`: найденный трек сначала добавляется/разрешается в каталоге. `GET /api/tracks/:id/playback` возвращает проверенный собственный descriptor с URL `/api/external-audio/:id` и отдельным `downloadUrl`, если право на скачивание существует. Реальные подписанные адреса CDN остаются только внутри процесса сервера.

Собственные аудио endpoints требуют авторизации и доступа к треку, поддерживают ranges; 401/403/410 источника обновляют истёкший URL один раз. Download без конвертации сохраняет исходный формат; `?format=mp3` отдельно проверяет convert и запускает FFmpeg. Обложки имеют same-origin endpoint и ограниченный дисковый кеш. Кеш аудио — на устройстве, не центральная библиотека MP3.

`GET /api/tracks/:id/audio-matches` показывает реальные кандидаты/оценку. `GET /api/admin/extractors` показывает независимую доступность/версии и очередь. `GET /api/admin/resources` показывает процесс Node: CPU относительно одного ядра, RSS, heap, external, p99 event loop, соединения и извлечение. Эти цифры не означают использование всей памяти/CPU машины.

## Нагрузка и проверка

Одновременно выполняется один worker по умолчанию, максимум три по конфигурации; очередь 16, ответ 2 MB, timeout 45 секунд. Выключение сервера/timeout завершает дерево процессов. Метаданные ограничены 200 записями с TTL, одинаковые запросы объединяются; обложки ограничены размером и общим кешем. До 16 аудиопотоков, только одна конвертация, backpressure, byte/time limits; отключение клиента отменяет поток и FFmpeg. Декоративные RAF/тикеры и поллинг плеера выключаются при скрытом клиенте; реальное разрешённое аудио остаётся активным.

Сетевые тесты проверяют отсутствие прав, отзыв, expired URL, ranges/416, download и запрет конвертации. Реальные запросы проверены для SoundCloud, YouTube/YouTube Music и spotDL. Короткий изолированный тест: одна настоящая socket-сессия, комната с 100 метаданными, 24 heartbeat за 43 секунды; 4 checkpoint-записи и 0 рассылок полного аккаунтного состояния. Это не длительный production benchmark и не доказательство отсутствия всех утечек. Сводные свежие результаты: `verification/2026-10-09/ecosystem-evidence.json`.

Остаются: физический фон/next на Android/Windows, Windows DSP, живые права и OAuth всего каталога, длительный профиль памяти и публикация обновлённого backend. Официальные embeds для музыки без разрешений намеренно не маскируются под собственное аудио.

Дополнительно проверен настоящий CC-BY трек SoundCloud в отдельном браузере с выключенным звуком: собственный `kind:audio`, ноль iframe, перемотка, продолжение при имитации hidden document, скачивание 3 282 650 байт аудио и 107 238 байт обложки в IndexedDB. Это не физическая проверка телефона/Windows. Доказательство: verification/2026-10-09/permitted-browser-proof.json.
