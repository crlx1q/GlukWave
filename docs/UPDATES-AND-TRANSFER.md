# Обновления и личный перенос в GlukWave27

## Обновление приложений

Первый переход с 26 на 27 выполняется обычным APK/установщиком. В 27 уже встроен новый процесс: при запуске Windows/Android приложение в фоне проверяет каталог сборок один раз за 24 часа для выбранного сервера. Одинаковые запросы объединяются; отсутствие сети не задерживает запуск музыки. В разделе «О приложении» проверку можно вызвать вручную.

Сравнение учитывает и версию, и номер сборки:1.2.1 новее 1.2.0, а 1.0.0+28 новее 1.0.0+27. Баннер предлагает загрузку, показывает прогресс и позволяет отменить. Перед установкой проверяются размер и SHA256 полного файла. Повреждённый файл не устанавливается; незавершённая частичная загрузка удаляется. После загрузки запускается обычный системный установщик с подтверждением ОС; скрытой установки нет. На Android может потребоваться один раз разрешить установку обновлений из GlukWave.

Сервер использует существующие `/api/releases` и `/api/downloads/:platform`. Он публикует только действительно существующие пакеты с совпадающими размером, SHA256 и датой сборки. Для Windows обновление требует EXE-установщик; ZIP остаётся отдельным переносным вариантом. Среди проверенных каталогов выбирается более новая версия, а не просто первый файл.

Оператор может загрузить пакет через существующую панель владельца или разместить проверенные `releases.json` и файлы в `RELEASES_DIR`. Скрипт `scripts/register-release.mjs` записывает обязательные метаданные, включая `builtAt`. Версии Android должны сохранять прежний сертификат подписи. Эта локальная поставка сама не публикует файлы на хостинг и не меняет установленное приложение.

## Личная медиатека

Открытые коллекции Spotify, Яндекса, SoundCloud и YouTube по-прежнему доступны по нику/ссылке без личного токена через публичный импорт. Для закрытых лайков и плейлистов в Spotify/Яндексе добавлено отдельное подключение собственным токеном.

В экране переноса выбери сервис, вставь свой access token и нажми «Проверить и подключить». Сервер сначала проверяет аккаунт и доступ к лайкам/плейлистам, затем открывается существующий выбор коллекций, треков и назначения: любимое или плейлист. Импорт сохраняет учёт повторов и обучение музыкального вкуса. Метаданные закрытых коллекций принадлежат аккаунту и не становятся общим публичным каталогом.

Spotify OAuth сохранён. Личный токен должен иметь доступ `user-library-read` и `playlist-read-private`; доступ приложения и ограничения площадки продолжают действовать. Истёкший личный токен нужно заменить. Для Яндекса в интерфейсе есть ссылка авторизации, предоставленная владельцем; доступность её внешнего приложения зависит от Яндекса.

Необязательный `YANDEX_MUSIC_TOKEN` на сервере используется только для общего поиска и публичного каталога. Личная библиотека запрашивается с отдельным пользовательским токеном. Личные токены зашифрованы существующим `TOKEN_ENCRYPTION_KEY`, не возвращаются в ответах и не записываются в настройки клиента или аудит. Поле очищается после сохранения, закрытия и смены аккаунта.

Проверки в этой поставке используют локальные HTTP-фикстуры; аккаунты и токены владельца не использовались. Новое подключение не объявляется гарантированным обходом ограничений стороннего сервиса.
