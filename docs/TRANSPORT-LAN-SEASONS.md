# Прямое воспроизведение, локальные устройства и сезоны

Итерации 1.0.0+9 и +10 продолжают существующий проект и сохраняют изменения владельца в Discord.

Собственный плеер получает доступные SoundCloud HLS-потоки через официальный серверный API `/tracks/{track_urn}/streams`. Используется полный AAC160 или MP3128 поток; preview/blocked не подменяются полным треком. Web декодирует поток в том же AudioElement, который подключён к EQ и MediaSession. Flutter использует explicit HlsAudioSource с Android audio_service и Windows mpv/DSP. HLS является обычным декодируемым аудио: для EQ не требуется предварительное преобразование в MP3.

Метаданные Spotify/YouTube могут сопоставляться с разрешённой SoundCloud-записью по исполнителю, названию, версии и длительности; сомнительное совпадение отвергается. Независимо лицензированный extractor/download остаётся отдельным приоритетным путём. Официальный API SoundCloud сам по себе не разрешает постоянное offline-кеширование: такой descriptor всегда `offline:false`, сегменты идут через ограниченный временный proxy без файлового кеша и без перекодирования. Обложки и разрешённые скачивания сохраняет существующая клиентская MusicCache. Один YouTube Data API key не предоставляет право скрыть видеоплеер, отделить аудио и скачивать любой ролик.

Сервер проверяет текущую сессию и доступ к треку на каждом запросе сегмента, включая отзыв/бан; OAuth-токены не попадают в CDN или URL. Временный grant ограничен одним треком и сессией. Все HLS manifests, variants, keys и segments переписываются на тот же origin; внешние redirects и произвольные адреса отвергаются. Root URL обновляется после403, клиент ограниченно восстанавливает HLS; очередь, concurrency, размеры manifests/segments/индексов ограничены. Реальные production credentials SoundCloud этой локальной проверкой не использовались: API transport в тесте изолирован, HTTP proxy и browser decoding настоящие.

Локальная сеть доступна в Flutter Windows/Android из панели устройств. Войдите в один аккаунт на обоих устройствах заранее. Включите локальное управление, создайте QR на ведущем устройстве и отсканируйте/вставьте приглашение на другом. Приглашение одноразовое, истекает через две минуты. Привязка не передаёт облачный bearer: отдельные ключи сохраняются в secure storage своего аккаунта, для каждой связи используется HKDF и AES-256-GCM с directional sequence/replay protection. Любое сопряжённое устройство управляет одним выбранным выходом и видит трек/позицию/громкость.

При переносе принимающее устройство сначала открывает уже скачанный разрешённый трек, затем прежний выход ставится на паузу и запускается новый. Ошибка подготовки сохраняет прежнюю музыку; ошибка запуска пытается вернуть прежний выход. Offline-only guard запрещает неожиданную сетевую загрузку пропавшего файла. Локальная очередь ограничена100 треками. Здесь нет передачи аудиофайла между устройствами: нужная музыка должна уже находиться в кешах обоих клиентов. Режим отделён от облачного Connect и комнат; чтобы вернуться к ним, выключите локальное управление. Есть heartbeat/reconnect и отзыв доверия. Отключённый ведущий не выбирается как новый выход автоматически.

Браузерный LAN/offline, IPv6 discovery, автоматическое обнаружение соседних Flutter-клиентов и передача разрешённых файлов остаются дальнейшей работой. Текущий QR содержит IPv4 локального интерфейса. Физические Windows/Android фон/выключенный экран/firewall/router не подтверждены автоматическими тестами двух loopback-клиентов.

Сезонные эффекты выключены по умолчанию. Доступны auto, снег, дождь, листья, солнечные лучи и две интенсивности. Автосезон использует северный календарь месяцев; можно выбрать вручную. Настройка доступна Free, хранится в существующих настройках аккаунта и на устройстве. Небольшое ограниченное число частиц не перехватывает нажатия; эффект останавливается в фоне, при reduced motion и удаляется после выключения.

У нижнего веб-плеера лайк перенесён в группу трека: устранён лишний ряд трёхколоночной сетки. Ползунки, размеры кнопок и мобильная компоновка используют тему приложения. Независимая оценка и полные проверки записываются в `verification/2026-10-10/transport-evidence.json`; сборки и ограничения в `outputs/VERIFICATION.md`.

Первичные условия: [SoundCloud API guide](https://developers.soundcloud.com/docs/api/guide), [SoundCloud API terms](https://developers.soundcloud.com/docs/api/terms-of-use), [YouTube Developer Policies](https://developers.google.com/youtube/terms/developer-policies).

Консоль использует предоставленный владельцем `ascii-art.txt`: убраны только пустые поля вокруг самого знака. В поддерживающем терминале знак получает лилово-мятный градиент; narrow terminal показывает компактный заголовок. Есть отдельные Connection/Live session/API activity, фактические RSS и heap, CPU процесса относительно одного ядра и счётчики запросов. Строки запросов окрашивают метод/статус/время; сообщения не могут вставлять управляющие ANSI-коды. `CONSOLE_STYLE=json` остаётся production default; `studio` можно явно включить на сервере, `compact` — только строки логов. Учитываются NO_COLOR/FORCE_COLOR, plain/16/256/truecolor режимы. Логотип выводится при старте; запрос статуса не повторяет весь знак и не запускает таймер перерисовки. Пример `outputs/GlukWave-server-console.txt` снят с настоящего изолированного локального сервера; это не нагрузка хостинга.

Доработка +10: каталожный embedUrl больше не используется автоматически ни сервером, ни вебом, ни Flutter. Сервер пробует независимые разрешённые адаптеры и отдаёт только audio descriptor; иначе возвращает локализованную ошибку недоступности. Публичный SoundCloud использует app OAuth, приватный — связанную сессию пользователя; единичный401 обновляет отклонённый токен под общей блокировкой. Сопоставление принимает также явно записанный «Артист — Название», убирает известный YouTube суффикс «- Topic» и сохраняет строгие проверки автора/версии/длительности. Яндекс-метаданные также могут сопоставляться с разрешённым SoundCloud-аудио. Атрибуция показывает настоящего загрузившего автора.

GET /api/health публикует только признак протокола playbackRevision:3/playbackMode:native-audio. GET /api/admin/playback требует администратора и возвращает счётчики/последние20 кодов отказов, загрузку/ограничения HLS без OAuth-токенов и CDN query. Это позволяет отличить старый сервер на хостинге от новой версии; health предыдущей версии не имел этих полей. Протокол не разрешает автоматически MP3 или офлайн для ограниченных треков.

Продолжение +10 по сообщению «все треки недоступны»: независимый yt-dlp теперь сохраняет HLS как доступный формат, вместо отбрасывания всех не-progressive результатов. Добавлен отдельный разрешённый HLS-прокси с проверкой сессии, прав, CDN, лимитов, завершения запросов и обновления403. Для Spotify/Яндекс возможен автоматический точный поиск лицензированного соответствия в YouTube Music, отказ spotDL не блокирует этот путь. На хостинге 10 октября прочитан health с ревизией2: новые изменения не публиковались агентом, массовая доступность живого каталога не объявляется подтверждённой. Подробности прав и актуальной проверки источника — PERMITTED-AUDIO.md.

Оформление +10: текст прокручивается только при измеренном переполнении, обложка пульсирует только при настоящем ожидании источника. Время и транспорт центрированы, кнопки и ползунки используют единую тему. Сезоны смягчены после обратной связи: лето — рассеянные движущиеся пятна тёплого света, без резких диагональных лучей; слои не перехватывают нажатия и прекращают движение в фоне/reduced motion. Вердикт окончательной проверки и собранные файлы фиксируются в outputs/VERIFICATION.md.
