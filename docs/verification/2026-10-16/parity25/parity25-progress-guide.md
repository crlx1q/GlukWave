# GlukWave +25 smooth playback progress

Production source was frozen on 2026-10-16 for independent evaluation. This is a presentation refinement of the existing player. It preserves the established geometry, cover hit testing, lyrics, Wave caption, icon timing, date ordering and scoped sorts.

## Clock and surfaces

- Web full/collapsed seek, phone footer progress rail, room seek and the existing popup mini share an isolated visible scheduler. No frame sets player Context state, calls a transport command, sends a socket message or writes media time. The existing state/network cadence is unchanged.
- Local web audio reads the actual decoded HTMLMediaElement time, playing/ready/ended state and playback rate. Fractional input values use step=any while custom keyboard steps preserve the original meaningful increment. The phone rail no longer has a second 700ms width transition, so an accepted seek can snap immediately.
- Mirrored/Connect/room UI reads the last accepted remote anchor; the existing 250ms presentation state ticks do not refresh its freshness. It extrapolates at most five seconds and clamps at duration. Embedded provider/mini samples have shorter bounded horizons. Mini reanchors the cross-window clock on receipt and propagates the remaining horizon, so its 500ms messages cannot make an old remote source advance forever.
- Canonical remote snapshots do not include playback rate. Remote/room interpolation retains the existing 1x snapshot semantics; local 1.5x/2x media time is accurate. This presentation change does not invent or change transport rate authority.
- The visible scheduler stops in a hidden document and for offscreen elements. Reduced-motion/power-saving presentation uses a 100ms timer between paints rather than a continuous 60fps loop; returning to view reads current authority.
- Native full player, bottom strip, desktop listening rail, desktop transport and compact player use the isolated PlaybackProgress subtree. Local decoded sources read physical player time; embedded/remote sources use bounded visual interpolation. Stopwatch time is independent of Flutter timeDilation. TickerMode, app lifecycle, scroll visibility and reduced motion control the visual work. A pending local selection whose displayed track differs from the decoder track immediately shows0/selected duration/paused until the matching source arrives; it cannot inherit the prior decoder time. Native audio.dart, notification services and synchronization authority were not edited by this implementation.
- Lyrics continue to derive cue positions from the actual playback stream. Visual timeline time is never supplied to lyric cue selection.

## Scrubbing

ContinuousRange retains pointer, touch and keyboard draft ownership during incoming snapshots and visual frames. The same draft drives thumb and fill. Release/quiet keyboard settlement commits once; cancel discards the draft and restores latest authority. The native DraftSlider is unchanged and remains the sole owner of its draft and seek callback; visual frames only supply its value property.
