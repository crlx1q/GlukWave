# Public collection import review

The existing GlukWave source cards now open a public lookup by nickname, profile URL or playlist URL for Spotify, Yandex Music, SoundCloud and YouTube Music. A GlukWave account and the existing import plan entitlement remain required. Provider sign-in is optional and only runs after an explicit connected-account choice.

The picker keeps the existing collection → track selection → destination → import result flow. It uses source-prefixed normalized track IDs, deduplicates page overlaps, supports loading more tracks, keeps a stable request ID through retries, and refreshes only the library after success. Public collections retain their original name when imported as a playlist. Public likes use `kind: 'likes'` and default to the likes destination. Unknown collection counts are labelled as public collections until the track response provides an exposed total.

Public/private/empty and partial-source explanations, input labels, Find, and loading state have English, Russian, Kazakh, Ukrainian, German and Spanish copy. Partial warnings appear before import and again in the result. Backend warning codes are rendered as localized human messages, including a safe generic fallback. Artwork uses actual returned images and the existing source marks. No generated artwork, provider widgets or embedded players were added.

## Implementation scope

- Web: `apps/web/src/provider-import.tsx`, source affordances in `pages.tsx`, `public-import-copy.ts`, and scoped `public-import.css`.
- Native: `apps/native/lib/ui/provider_import.dart`, source affordances in `app.dart`, and `public_import_strings.dart`.
- Focused native tests: `apps/native/test/public_import_test.dart`; the existing connected import regression in `refinement20_ui_test.dart` now explicitly chooses connected mode and expects normalized IDs.

Existing playlist/cover/Connect changes were preserved. No release version, package or build output was changed by this implementation agent.

## Verification

`npm run check --workspace @glukwave/web` validates web types. `flutter analyze --no-pub lib/ui/provider_import.dart lib/ui/public_import_strings.dart lib/ui/app.dart test/public_import_test.dart` checks the native scope. Native runners must have the exclusive slot.

`flutter test --no-pub test/public_import_test.dart test/refinement20_ui_test.dart --name 'import|Public likes' --reporter expanded` covers all four public provider UI flows, 320/375/desktop layouts, 125% text, paging overlap, normalized selected IDs, retained playlist titles, one-intent retry, public likes destination, exposed count updates, no automatic OAuth, narrow library refresh, empty/error/retry, stale query/account results, and a 320 keyboard-inset state. Seven baseline focused tests pass; see `work/qa/public-import-native-tests.log` and `public-import-native-analyze.log`. The independent evaluator additionally passed nine native checks. A distinct final regression, `Public import paging preserves deselection while selecting only newly seen normalized IDs`, passes with JSON evidence in `public-import-native-overlap.jsonl`; final changed-file analysis is clean in `public-import-native-overlap-analyze.log`.

The isolated web fixture is started with `node work/qa/public-import-preview-server.mjs`, then `node work/qa/public-import-browser.mjs`. Its URL is `http://127.0.0.1:5206/app/#sources`. It serves the actual React application and original shipped artwork with mocked public-provider responses. Requests and screenshot evidence are in `public-import-web-proof.json`, `public-import-browser.log` and `public-import-web-*.png`. Browser transport/test fixture failures are distinct from live provider behavior. A visible import error uses HTTP409 in the fixture; the existing action transport automatically retries HTTP502–504 with the same intent, so those responses are not suitable for testing an explicit Retry button.

Final web overlap/scroll changes have a separate passing four-check proof in `public-import-final-delta-proof.json`, generated by `public-import-final-delta.mjs`, with `public-import-web-spotify-320-final-result.png`. The independent evaluator's all-four-provider baseline and final extra scenarios are stored as `public-import-evaluator-web-proof.json` and `public-import-evaluator-extra-proof.json`. Each Vite fixture uses its own dependency cache to avoid invalidating another fixture's client. The browser harness polls actual rendered state because the installed CLI occasionally returned a transport timeout from its built-in wait command despite the expected DOM already being present.

Native screenshots are `native-public-import-*.png` in this directory. Both clients reset scroll position on stage changes so the success heading and count appear immediately. Both preserve a deliberate deselection when an overlapping next page returns the same track; only newly exposed IDs are selected automatically. Dialog content scrolls safely with a software keyboard and larger text. Web dialog dimensions compensate for the existing font zoom; source button labels wrap at 320/125%. Unconfigured source labels explain the public route instead of claiming import is unavailable.

These UI fixtures do not prove live public retrieval. Root's backend tests and live public metadata checks cover the upstream adapters separately. Protected/private material is not made available by this flow. Independent evaluator results are recorded separately before root integration and packaging.
